# 移动端同台对比交集时间轴与沉浸监看交互重构

> 在双视频同台对比与慢放监看中，面对并集时间轴导致单边黑屏无动作、左右分区画面过小、微调控件繁复截断以及导出视口溢出的问题，我决定：
> 1. 全面采用重叠交集（Intersection Interval）作为统一时间轴唯一有效范围，并支持锚点前 1s 快速起播；
> 2. 调大左右分区人物投影比例至 60% 并将默认对比模式设为左右分区；
> 3. 精简 1F 与 20ms 级步进按钮，升级为直接数字编辑锚点与顶栏全流程可点改 BPM；
> 4. 重构空间标定防遮挡角标（黄线左下、绿线右上）与导出台横屏自适应弹性布局，补齐预览播放能力；
> 以达成移动端横屏下极简、无冗余、大画面、无遮挡的高效 WOTA 艺扒技体验，并接受交集范围之外的超长尾部内容被自动滤除的代价。

**历史注记（2026-11-25 核对）**
>
> 本篇第 2 条「调大左右分区人物投影比例至 60%」已被后续记录逐步修订：
> AgDR-0013 提升至 68%~70%，AgDR-0014 收敛至 65%~66%，当前实现为半区高度的 65.5%
> （见 `src/core/geometry.ts:187`）。本篇第 1、3、4 条仍然有效。

## 考虑过的方案

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| **方案 A：保持并集时间轴，但允许两端黑屏** | 两个视频的所有物理帧都能被播放到 | 用户在对比台和导出台经常滑入只有单一视频动作的盲区，失去同台对比意义；导出视频包含大量单边黑屏时间 |
| **方案 B（入选）：彻底切换为对齐后的有效重叠交集** | 每一帧都有双视频对照，时间轴紧凑有力，导出视频全程高质量同台；操作直觉明确 | 某一视频若明显长于另一视频，其多余部分在对比台中无法播放 |
| **方案 C：保留平铺 1F 与 20ms 多级步进控件** | 理论上具备超高精度逐帧控制 | 移动端横屏空间被严重挤爆，导致右侧关键的 BPM 加减按钮被截断，且用户在移动端直接输入数字更加迅速 |

## 决定

选 **方案 B 并配套执行移动端极简紧凑交互重构**，因为：
1. WOTA 艺同台对比的核心价值在于「同一招式动作的毫秒级同步校验」，一旦某一方视频超出范围变成单边黑屏，同台对比即刻失效，因此并集区间是伪需求，交集区间才是唯一的真实对比源；
2. 移动端横屏高度狭窄（360px~450px），导出台面板必须自适应收缩，必须保证“开始渲染导出”操作按钮 100% 处于第一视口内；
3. 用户习惯直接输入数字设定锚点，移除 1F 与 20ms 能够彻底释放横向空间，保证 BPM 加减按钮与数值输入完全舒展露出。

## 代价

- 我们接受：若两个视频长度差异极大（例如 40s 对比 190s），对比台和导出台将仅截取两视频重合的几十秒交集，不展示长视频的后续单独内容；
- 我们放弃：在空间标定、音频对拍与对比台中保留 1F 逐帧按键（保留时间轴拖拽与直接数值输入）；
- 后面要还的债：如果未来用户需要跨视频片段滑动比较不同副歌段落，需要通过重新设定锚点来平移交集窗口，而非在时间轴上自由漫游。

## 什么情况下需要重新讨论

- 如果用户明确提出需要支持“单视频超长伴奏预览”且要求在同台对比台中单独保留单边画面的播放能力时，重开此记录。
